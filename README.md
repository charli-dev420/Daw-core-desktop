## What DAWWW-CORE actually is

DAWWW-CORE is not a cloud music service with a sequencer bolted onto it, and it is not a small browser sketchpad designed only to make loops.

It is a DAW-shaped application built around a complete local project lifecycle.

Open the Desktop app and the first surface is the **project launcher**: create a session, import an existing `.dw`, or restore a local project. Once inside the Studio, the same project moves through the sequencer, piano roll, arranger, instruments, effects, automation and mixer until it is ready to be rendered or exported.

The important part is that these are not disconnected mini-tools. They operate on the same session and the same project model.

A typical DAWWW-CORE session looks like this:

```text
Create / import / restore
          ↓
Choose an instrument
          ↓
Write a pattern in the sequencer
          ↓
Refine notes or step behaviour
          ↓
Build the song in the arranger
          ↓
Shape instruments + effects + automation
          ↓
Route and balance in the mixer
          ↓
Export audio / stems
          ↓
Keep or move the project as .dw
```

That is the product in one line: **a browser-based production workflow where the musical session remains a portable project instead of becoming inseparable from a hosted account.**

## The workflow is intentionally hands-on

The Browser is not only a file list. It exposes the instruments available to the project and groups them by musical role. An instrument can be brought into the writing workflow, programmed in the sequencer and then edited in more depth without changing application or project context.

The sequencer is also more than an on/off drum grid. Individual steps can carry musical behaviour such as **velocity, probability, gate length, ratcheting, articulation and timing offset**. That makes it possible to add variation, loosen rigid patterns and create rhythmic detail before moving into the piano roll or arranger.

For pitched material, the **piano roll** provides note-level editing. For sound design, instruments expose their own dedicated editors instead of forcing every sound through the same generic panel. The Electric Piano, drums, synths, orchestral voices and other instrument families can therefore present controls that make sense for the sound being edited.

Once the material is written, the project moves naturally into the **arranger** for song structure and then into the **mixer** for routing, levels, processing and master control. Automation remains part of that same session, so changes in effects or parameters can be written into the project instead of performed manually on every playback.

## More than a blank DAW shell

A fresh DAWWW-CORE project already contains a substantial internal sound palette. The current built-in registry includes **more than 50 instrument engines**, plus a sampler, organised into families such as:

- **Drums** — kick, snare, hand clap, closed/open hi-hat, low/mid/high toms, cowbell, rimshot, claves and maracas.
- **Bass** — sub bass, acid bass and Reese bass.
- **Electronic** — mono lead, poly synth, pluck, arpeggio synth, chiptune, FM keys and noise/transition FX.
- **Pads** — warm, glass, choir, evolving and ambient engines.
- **Keys & bells** — acoustic piano, electric piano, clavinet, tonewheel organ, celesta, music box and tubular bell.
- **Guitars** — nylon, steel-string, clean electric and driven electric.
- **Orchestra** — dedicated strings, brass and woodwind engines including violin, viola, cello, contrabass, trumpet, French horn, trombone, tuba, flute, oboe, clarinet and bassoon.

The point is not to replace every external plugin ever made. The point is that **a new project is immediately capable of becoming a complete musical sketch or production without requiring a separate plugin collection just to make sound.**

The built-in processing layer currently includes **16 effects**: an 8-band parametric EQ, compressor, convolution reverb, tempo-synced delay, chorus, flanger, phaser, distortion, filter, gate, limiter, saturator, tremolo, vibrato, bitcrusher and utility processing.

## `.dw` is the centre of the product

The `.dw` format is not just an export option at the end of the interface. It is the portable representation of a DAWWW-CORE project.

The Desktop application keeps the working session local-first, but a project also needs a way to leave the browser safely. `.dw` provides that path: **save it, move it, archive it, import it again or restore it on another compatible DAWWW-CORE surface.**

This matters because browser applications are often designed around a remote database as the only authoritative copy of a project. DAWWW-CORE deliberately avoids making that the creative contract.

The product model is instead:

```text
Local working project
        +
Portable .dw project
        =
A session that does not depend on mandatory cloud storage to exist
```

Accounts and online services can exist around the application, but the creative project is not designed to become a server-owned object just because the workstation runs in a browser.

## Desktop now · Android next

### Desktop — available now, no payment

The Desktop Web version is the current DAWWW-CORE product surface. It is built for the larger screen and dense controls required by the sequencer, piano roll, arranger, device editors and mixer.

There is **no payment flow on Desktop**. The Studio can be opened directly from the web, and the PWA-oriented architecture allows the browser experience to behave more like an installed application where the platform supports it.

[**Launch the Desktop Studio →**](https://dawww-core-local.com/app)

### Android — coming on subscription, with the same project

The Android version is not planned as a separate mobile toy or a read-only companion app. It is being built as the mobile continuation of the same DAWWW-CORE workflow.

Android will be offered **on subscription**, with **100% Desktop ↔ Android project compatibility as the product target**. The same `.dw` project contract is the basis of that continuity:

```text
Desktop project
      ↓
     .dw
      ↓
Android project
      ↓
     .dw
      ↓
Desktop again
```

Cross-device therefore does not mean that every project must be uploaded to a cloud before it can move. The portable project remains part of the design.

## Why put this much of a DAW in a browser?

Because the browser gives DAWWW-CORE two things at once: **immediate access** and a modern application runtime.

The audio layer uses **Web Audio API** and **AudioWorklet** for real-time processing, while TypeScript, React and Vite provide the application and UI layer around the engine. Local browser storage and the `.dw` pipeline handle project persistence and portability. PWA support brings the distribution model closer to an installed desktop application without requiring a traditional installer as the only entry point.

The goal is not “a DAW, but in JavaScript” as a technical exercise. The goal is to use the web where it is useful — distribution, access, portability and rapid updates — without giving up the structures expected from a production tool.

## What DAWWW-CORE does not currently pretend to be

The current product direction is deliberately bounded. DAWWW-CORE is **not currently built around** mandatory cloud project sync, real-time collaboration, iOS support or a plugin marketplace.

Those omissions are intentional public scope, not features hidden behind this showcase. The focus is the workstation itself: playback, writing, instruments, effects, automation, mixing, project recovery, `.dw` portability and export.

## Public technology stack

`TypeScript` · `React` · `Vite` · `Web Audio API` · `AudioWorklet` · `PWA` · browser-local storage

The production codebase also contains dedicated QA, project-recovery, compatibility, observability and release tooling. That implementation remains private; this repository presents the product rather than exposing operational or security-sensitive internals.

## About this repository

`Daw-core-desktop` is the **public product showcase for DAWWW-CORE**.

The production application and audio engine are developed in a private codebase. This repository exists to make the product understandable from the outside: what it does, how a session works, what is available today and where the platform is going next.

It is **not** an open-source distribution of the production engine. Deployment configuration, private QA artifacts, provider contracts, security mechanisms and other sensitive internals stay outside this repository.
