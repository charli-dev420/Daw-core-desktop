# DAWWW-CORE Support

DAWWW-CORE Desktop is available as a browser-based, local-first DAW. This repository is the **public product showcase and feedback surface**; the production implementation is maintained privately.

## Before opening an issue

Check the public resources first:

- Studio: https://dawww-core-local.com/app
- Documentation: https://dawww-core-local.com/en/docs
- Tutorials: https://dawww-core-local.com/en/tutorials
- FAQ: https://dawww-core-local.com/en/faq
- Status: https://dawww-core-local.com/en/status

## Report a product bug

Use the **Bug report** issue form when the visible product behaves unexpectedly.

Please include, when relevant:

- the exact action you performed;
- what happened and what you expected;
- Desktop Web or Desktop PWA;
- browser and browser version;
- operating system and device;
- approximate project size: tracks, instruments, effects, samples and duration;
- whether the problem is reproducible in a new project;
- screenshots or a short screen recording if they contain no sensitive material.

Do **not** upload private `.dw` projects, credentials, tokens, personal information or licensed/private audio unless you intentionally want that material to become public.

## Request a feature

Use the **Feature request** form. Describe the workflow problem first, then the behavior you would like DAWWW-CORE to provide. Concrete production use cases are more useful than implementation proposals.

## Request an instrument or effect

Use the **Instrument / FX request** form. Include the sound or processing role, the controls that matter in practice and an example use case. Requests are evaluated as product needs; this repository does not expose the private production implementation.

## Cross-device feedback

Use the **Cross-device feedback** form for `.dw` portability and Desktop ↔ Android workflows. The project contract is designed around one portable `.dw` model rather than a reduced mobile project format.

For a useful report, describe:

- source platform;
- destination platform;
- how the `.dw` was transferred;
- what opened correctly;
- what differed, if anything;
- whether instruments, effects, samples, automation and arrangement were preserved.

## Security issues

Do **not** report vulnerabilities in a public issue. Follow [SECURITY.md](SECURITY.md) instead.

## What this repository does not provide

- access to the private production source code;
- support for third-party modifications of the production application;
- guarantees that every requested feature, instrument or effect will be implemented;
- recovery of data that was never exported or no longer exists in the user's local browser/device storage.

For ordinary product questions, GitHub Issues and the public documentation are the preferred starting points.
